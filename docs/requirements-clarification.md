# Уточнённый объём тестового задания

## Подтверждено компанией 20.10.2026

1. У каждого производителя/поставщика собственные форматы масок. Сейчас достаточно правил HI-LEX из предоставленного ТЗ. Архитектура должна позволять добавлять новые форматы.
2. Каталог товаров не загружается. Система должна перечислять **все теоретические артикулы**, соответствующие маскам сертификата. Проверка существования товара и связь «товар — артикул» вне рамок.
3. Типичный формат сертификата — PDF. OCR не требуется: сканированные документы без текстового слоя могут быть отклонены с понятной ошибкой.
4. Формат итогового документа компанией пока не уточнён.

## Последствия для реализации

- Прежний сценарий «загрузка каталога CSV/XLSX + поиск совпадений» не соответствует основному требованию и должен быть заменён.
- Для HI-LEX одна маска с четырьмя независимыми позициями [A-Z0-9] описывает 36^4 = 1 679 616 артикулов; 38 масок — 63 825 408 артикулов.
- Полный результат нельзя целиком держать в памяти или напрямую формировать в одном HTTP-ответе Vercel.
- Результат целесообразно выгружать в CSV/ZIP частями с проверкой свободного места и лимитов инфраструктуры. Excel поддерживает максимум 1 048 576 строк на лист.
- Правила должны иметь отдельные версии и тесты. Предложения LLM по новым правилам не применять без валидации и подтверждения.
- Сканированные PDF без текстового слоя не распознаются, потому что OCR вне рамок ТЗ.
- Требуется контроль лимитов, статусов задачи, прав доступа и временного хранения выгрузок.

## План

1. Вынести набор правил HI-LEX в версионируемую конфигурацию.
2. Добавить безопасное извлечение текстового слоя PDF и масок.
3. Реализовать ленивый перечислитель артикулов и тесты количества, уникальности и граничных значений.
4. Организовать фоновую генерацию CSV/ZIP и контролируемую выдачу файлов.
5. Перестроить UI под один сертификат и прогресс генерации; удалить обязательную загрузку каталога.
6. Провести нагрузочные и защитные проверки перед сдачей.
