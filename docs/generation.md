# Уточнённая модель проверки сертификатов

## Принятое решение

В сертификате содержатся маски, представляющие все допустимые артикулы.
Перебирать и хранить каждую возможную комбинацию **не нужно**.

1. Пользователь загружает сертификат PDF с текстовым слоем, DOCX или TXT.
2. Система распознаёт и валидирует маски HI-LEX относительно утверждённого списка.
3. Интерфейс показывает все найденные маски и позволяет экспортировать список в CSV.
4. Пользователь может ввести один артикул и проверить, соответствует ли он какой-либо маске сертификата.
5. Наличие артикула в фактическом каталоге товаров не проверяется. Загрузка каталога не входит в основной пользовательский сценарий.

Для HI-LEX маска `4VB****` означает: ровно семь символов, первые три — `4VB`, последние четыре — из `A-Z0-9`. Для проверки достаточно сравнения по правилу; генерация 36^4 комбинаций не нужна.

## Ограничения

- OCR вне рамок задания: PDF без текстового слоя получает объяснимую ошибку.
- На данный момент поддерживаются только правила HI-LEX из задания.
- Для других производителей предусмотреть отдельные конфигурации и тесты; не применять неподтверждённые правила от LLM.
- Загруженный сертификат интерпретируется в пределах поддерживаемого синтаксиса. Неизвестные маски отклоняются.
- Нужны полноценные интеграционные тесты и проверка деплоя перед сдачей.
